# Introduction

Git worktrees are a powerful Git feature that let you work on multiple branches at the same time. But many developers still search for:


  - rename git worktree

  - how to rename git worktree

  - git worktree folder name change


# Why Developers Need to Rename Git Worktrees ?

Common reasons include:

  - the branch name changed

  - Jira / ticket number updated

  - repo structure evolved

  - need for cleaner naming conventions

  - managing many parallel worktrees

  - readability and project organization

Good naming improves productivity and makes your Git worktree environment easier to manage.

# Git Does NOT Support Renaming a Worktree

There is no official command like:

```bash
git worktree rename
```

And if you try to rename the worktree directory manually, Git will break because the worktree path is indexed in the repo’s internal metadata:

```bash
.git/worktrees/<worktree-name>
```

Renaming the folder directly leads to errors such as:

```
fatal: '<path>' is not a working tree
```

This is why developers search for alternatives to rename Git worktrees safely.


# The Correct Way to Rename a Git Worktree (Safe Method)

To “rename” a Git worktree without breaking your repository, you must:

1. Remove the old worktree path (without deleting the branch)

```bash
git worktree remove <old-worktree-path>
```

This safely removes the worktree metadata.

2. Add the worktree again using the new directory name

```bash
git worktree add <new-path> <branch-name>
```

This is the recommended method for renaming a Git worktree.

# Example: Renaming a Git Worktree Folder

Suppose your current worktree directory is:

```bash
worktrees/feature-login
```

You want to rename it to:

```bash
worktrees/login-ui
```

Run:

```bash
git worktree remove worktrees/feature-login
git worktree add worktrees/login-ui feature/login
```

This process preserves:

- your branch

- all your Git history

- your changes

And gives you a clean, correctly named worktree directory.
